# Design decisions about the skill itself

| ID | Decision | Why | Evidence | Change if |
|---|---|---|---|---|
| D-001 | Skill text is **English**, with Persian examples, terms and copy samples; run reports and user-facing summaries are Persian | Agents follow precise English instructions most reliably and cheaply; Persian is kept where the *content* is Persian. The user can veto | RECOMMENDATION | A Persian-speaking team needs Persian instructions: add a translated overlay rather than duplicating the source of truth |
| D-002 | One router `SKILL.md` + 21 focused references + templates + scripts, all one hop from `SKILL.md`; the process-of-evolution files live in `meta/` outside the skill | Progressive disclosure: the agent pays tokens only for what the phase needs; evolution notes must not ship to runtime | Agent Skills spec: body < 500 lines and < ~5000 tokens recommended, references one level deep (agentskills.io/specification, fetched 2026-10-02, P); Claude Code docs: every SKILL.md line is a recurring cost, description+when_to_use capped at 1,536 chars in listings (code.claude.com/docs/en/skills, 2026-10-02, P) | Usage shows agents skip files or load too much |
| D-003 | Skill name `persian-website-builder` (lowercase, hyphens, equals directory name); frontmatter has `name`, `description`, `compatibility`, `metadata.version` | Matches the spec's constraints (name ≤ 64 chars, no leading/trailing/consecutive hyphens, description ≤ 1024 chars, `metadata` is a string map) | Same spec pages (P) | Spec changes (re-check each quarter, OQ-20) |
| D-004 | Helper scripts are Node ESM with **zero package dependencies**; only the two browser tools need Playwright | Anyone can run them; they ship with tests; fewer supply-chain risks | RECOMMENDATION | A needed check cannot be done without a dependency: isolate it as optional |
| D-005 | **Maturity scale M1/M2/M3 per module** published in `SKILL.md` §10 | Honest depth signal for agents and humans; prevents authority by length | RECOMMENDATION | Never raise a maturity without a recorded validation or field use |
| D-006 | **Evidence register with IDs** referenced from guidance, mechanically linted (cited IDs exist, dates within volatility windows) | Makes "evidence-driven" checkable; stale claims surface automatically | RECOMMENDATION | Register grows too large: split by domain, keep IDs permanent |
| D-007 | **No framework or library names/versions inside guidance** except as examples of categories | Framework state changes fast; versions stored here would silently rot | Principle | A stable, verified list emerges and can be date-stamped in the register |
| D-008 | Decision frameworks state inputs → rule → default → **change-if trigger**, and ADRs record weights **before** scoring | Prevents taste and rationalization | Principle | |
| D-009 | Process proportionality (Lite/Standard/Heavy) with a non-negotiable **release floor** | Avoids both over-process and under-quality | RECOMMENDATION; to be tested in real projects (OQ-18) | Field data |
| D-010 | The `lint-skill.mjs` tool and its tests live in `meta/tools/` | It maintains the skill; it is not part of the runtime skill | | |
| D-011 | **Persian Web Ecosystem = five logical parts** (Skill, Contract, Foundry, Evaluator, Corpus) built on the existing skill. Physical folders appear only with their first real artifact; nothing is moved | The owner's brief; the skill's install entry point and coverage must stay; empty scaffolding is bloat | `MASTER-BRIEF.md` | A folder move is justified by a reproducible execution failure |
| D-012 | **Two axes for results**: execution status of each check (pass / fail / warn / info / incomplete / unknown / skipped / not-applicable) is separate from the run outcome (PASS / CONDITIONAL / FAIL / INCOMPLETE). Only PASS passes; a skipped or incomplete check is never success. Exit codes 0 (PASS/CONDITIONAL), 1 (FAIL), 2 (could not run), 3 (INCOMPLETE) | Run 2 reproduced silent success in four tools and in `node --test` (RT-013..RT-015) | `scripts/verdict.mjs`, tests in every tool | CI integrations need finer codes |
| D-013 | **Evidence is bound to content and environment**: sha256 per file + one `contentHash` of the tested scope, node/playwright/chromium/os, git head and dirty flag. The commit SHA is informational; `--verify` returns STALE when content or environment differ | An old PASS must not describe new content | `meta/tools/run-tests.mjs` | Evidence needs signing, or scope definitions grow |
| D-014 | **Scheduled-run work selection**: failing test / regression / invalid evidence first; then security, money or licence risk tied to the current work; then the current stage's open problem. One problem per run. Research questions are pulled in by the stage, not by a separate "next research target" | Resolves the conflict between the old procedure and the owner's plan | `PROCEDURE.md`, `ROADMAP.md` | |
